# DAIINAS v4.2 [P0] — KuCoin Exchange Control Plane: discovery, read-only account sync, external intervention and guarded orders

## Owner intent and actual delivery
Codex must make DAIINAS **orient in KuCoin at connection time** like a reliable portfolio manager, not merely fetch prices. At startup discover what account and trading mode are actually available, current supported instruments, 1m/5m/other historical/live chart candles, multi-symbol watchlists, prices, actual account balances, free/locked funds, liabilities/margin, **all open orders**, fill history and **all open positions** within each explicitly authorized account scope. Detect operator actions in native KuCoin UI or via a separate tool such as Bitsgap; preserve operator control. Then continuously maintain reconciled state with private WebSocket updates plus periodic/bounded REST resynchronization. Design a future order place/edit/cancel/close route but do NOT send actual orders yet.

**Critical sequencing:** A `READY_TO_OBSERVE` account may be reached once read-only reconciliation succeeds. `READY_TO_TRADE` is a SEPARATE permission state, BLOCKED until the owner explicitly authorizes the particular market type, real-order infrastructure/security and legal UK product eligibility. Never claim full exchange control or live Hedge support solely from docs or a public connection. **Do not request, paste or commit API keys, secrets, passwords, passphrases, wallet private keys, seed phrases**. A fully disclosed credential must be revoked/rotated if actual exposure is established; do not infer this from interface screenshots supplied as an architectural example.

## Official API architecture (2026-11-01 verified documentation)
- KuCoin [API Introduction](https://www.kucoin.com/docs-new): distinguish Classic Account Spot / Classic Futures and Unified Trading Account (UTA) with a capability matrix, supported API versions, per-endpoint account type and permission. UTA API **V2** migration has breaking schema, timestamp and auth behavior. Explicitly negotiate or query actual account mode; don't assume `positionSide` or Hedge availability.
- **Public Market APIs**: supported Spot/Futures symbol catalog and metadata (status, base/quote, tick/lot/multiplier, min notional, fees, leverage where relevant), ticker, best bid/ask, historical klines, public WS live candles/trades and sequence-verified L2, current funding where applicable, announcement/status; as-of clocked provenance. Reuse existing `daiinas/providers/kucoin.py` and continuous observer, don't rebuild validated public feed. Chart OHLCV is derived from exchange candles/observations, not fabricated.
- **Private General read-only**: authorized Classic/UTA account, holdings/balance/free/locked/borrowed, cross vs isolated margin, active/conditional order list (paginate), historical executions/fills, stop/TP/SL, current positions per `(accountId, marketType, instrument, positionSide)`, margin/maintenance and available reserve; private WS order/execution/balance/position update topics **only if supported for actual account mode**. REST startup snapshot and ongoing checkpoint/resync are mandatory. KuCoin [private order WS UTA](https://www.kucoin.com/docs-new/3470346w0), [private classic Futures order events](https://www.kucoin.com/docs-new/3470090w0), and [rate limits](https://www.kucoin.com/docs-new/rate-limit-rule-uta). The General permission is read-only; no signing order endpoints until expressly authorized.
- **Future Spot / Futures trade permission**: separate keys/scopes, allow-listed VPS IP and secret manager, platform/operator authorization gates; isolate per-account adapter and enforce **least privilege**. Explicitly prohibit Withdrawal, Transfer, Earn and unrestricted account-mode changes. Historical Futures Hedge support on an endpoint does not prove this UK user's account is allowed to use the product.
- KuCoin docs: [UTA V2 place order](https://www.kucoin.com/docs-new/v2/rest/ua/place-order), [Spot order](https://www.kucoin.com/docs-new/rest/spot-trading/orders/add-order), [Private order change WS](https://www.kucoin.com/docs-new/3470346w0); use these for interface design only and validate latest schemas at implementation.

## State machine / what it means to orient itself
Lifecycle: `OFFLINE -> PUBLIC_CONNECTED -> PRIVATE_AUTHENTICATED_READONLY -> DISCOVER_ACCOUNT -> SNAPSHOT_BALANCES -> SNAPSHOT_OPEN_ORDERS -> SNAPSHOT_POSITIONS -> SNAPSHOT_FILLS -> REPLAY_BUFFERED_WS_EVENTS -> RECONCILED_READONLY`. Record `source_event_id`, mode, UTC/exchange timestamps, request IDs, account/symbol scope, last WS sequence and REST cursor; cold start may buffer WS events while snapshots are paginated. No `RECONCILED_READONLY` until all required scopes are consistent and not stale. On WS gap, rest error, permission mismatch, unknown contract, clock skew, stale account view or snapshot conflict: immediately `DEGRADED` (no automated entries), log exact incompleteness, recover via fresh REST snapshot and idempotent event catch-up. Treat reconnection as normal, not duplicate funding/trading events.

**Owner live interventions:** No assumption that DAIINAS owns all orders. Classify exchange objects as `OWNED_BY_DAIINAS` only when provable by persisted clientOid/order ID & account identity, `EXTERNAL` for known-other IDs where grounded, otherwise `UNKNOWN`. Distinguishing Bitsgap from manual UI may be IMPOSSIBLE through API alone: do not invent provenance. Public/private pushes and REST reconciliation must detect any new/modified/cancelled/executed third-party order, partial fill, changed stop, funding settlement, liquidation or manual transfer, and immediately revise balance, position exposure, capital availability and risk. Unknown external order/position => no auto-cancel or auto-close; enter `EXTERNAL_INTERVENTION` pause/new-order-block and notify owner. Provide optional explicit operator `ADOPT`/`IGNORE_READONLY`/`PROTECT` workflow in future, with previewed risk and durable approval. If an external order reduces a DAIINAS position, do not restore it automatically or double-enter. If one external action raises portfolio risk, no new order should be submitted while unreconciled.

## Operator controls (separate from exchange-derived data)
Commands: `AUTO_ALLOWED` [only on approved market products], `PAUSE_NEW_ENTRIES`, `RESUME_AFTER_RECONCILIATION`, `STOP_NEW`, `READ_ONLY`, `EMERGENCY_RISK_OFF` (only executed after explicit operator pre-authorization and validated order gateway), and per-symbol `BLOCK/ALLOW`. Pausing stops automation entries but not accounting, WS subscriptions, existing stop/exit risk monitoring or read-only sync. Never silently cancel user/other bot orders; cancel only proven owned orders. Emergency-close must not exist in read-only phase. Record who switched control, time, reason, current account state, and acknowledged effect. One central order owner/coordinator with transaction guard, durable lock and `clientOid` idempotency prevents two DAIINAS processes issuing duplicate orders. Parallel Bitsgap orders are external and detected, not controlled.

## Orders, future gated execution and 'instant orientation'
Build explicit side-effect-free interfaces for `inspectMarket`, `inspectAccount`, `inspectOrders`, `inspectPositions`, `reconcile`, `previewOrder`, `proposePlace`, `proposeCancelOwned`, `proposeCloseOwned`, `operatorOverride`, `killSwitch`, `health`. All order proposals run Capital Ladder, risk aggregation, asset eligibility, min-lot, margin/free-cash, 2% net expectation, verified quote/liquidity, parent source account, per-symbol policy and global budget checks. Order/fill lifecycle: `PROPOSED -> RISK_APPROVED -> AUTHORISED -> SUBMITTED -> ACK_PENDING -> ACCEPTED/PARTIAL/FILLED/CANCELLED/REJECTED/UNKNOWN`, always verify ACK and reconcile uncertain outcomes by clientOid before retry; account for maker/taker fee and partials. A timeout after submit is NOT failure and must not resend blindly. If no valid private API permission, code must return `EXECUTION_DISABLED` without contacting trade endpoints. No funds transfer/withdrawal capability. Never automatically re-open manually closed trades or re-arm cancelled orders.

## Capital / portfolio reconciliation
- LEGACY 8 USDT remains regression only. V4 opening amount comes from the actual eligible, settled exchange account **after** read-only snapshot verification, or from separate user-selected explicitly hypothetical PAPER seed. Do not add MetaMask funds to KuCoin account equity or treat planned 60/100 as confirmed capital. See issue #10, `docs/V4_FUNDED_ACCOUNT_BOOTSTRAP.md` and `AGENTS.md`.
- Account namespaces MUST be isolated (Classic Spot, Classic Futures, UTA, subaccounts) and quantity/margin not equated to free cash. Exchange balances and simulated accounts must remain separate. Reconcile deposits/withdrawals as EXTERNAL flows, not realized profit. Reserve is not safe if within pledgeable/cross-margin collateral. No product eligibility => no real orders.
- Multi-symbol LONG/SHORT optional hedges are two position slots; hedge campaign accounts for winning AND losing sides and exact fees; operator manual counterpart affects portfolio risk immediately. Preserve 3% risk step and 6% HALT, and 10-slot capacity; zero trades valid.

## P0 acceptance tests and audits
1. Fresh Classic Spot, Classic Futures, UTA mocked initial snapshots each build correct catalog/balance/order/position view; invalid/missing permissions -> safe state. Test UTA V2 timestamp formats, schema variants and correct endpoint choice. No private secrets in fixtures.
2. Cold startup with private WS event arriving between REST pages; buffer/merge exactly once without missing external fills; replay sequence, restart and idempotent ledger checkpoint. Compare consistency of order sums, fees, cash, open margin and available funds.
3. Operator adds manual order, Bitsgap adds unknown order, partially fills, modifies TP/SL, cancels, deposits/withdraws, moves margin, closes half a position. Each event updates reconciled state, triggers `EXTERNAL_INTERVENTION` when risk ownership uncertain, and **does not** automatically cancel/replace third-party orders. Proven order attribution only.
4. Restart with open positions and orders originating earlier; no re-open, no duplicate clientOid/order send; all open or exit-pending symbols remain subscribed/pinned.
5. WS disconnect/replay gap, REST timeout, `429`, credential revocation/permission denial, account mode change, delisted instrument, symbol mapping collision, inconsistent clock, stale data -> `DEGRADED`, entries blocked and diagnostic. Backoff+jitter subject to KuCoin quotas.
6. Previews for `place/cancel/close` pass or reject exact funds, min notional, tick, step, fees, leverage, liquidity, margin, portfolio correlation, reserve and account permissions. Ensure ALL actual trade calls disabled at every possible code path by default; forbidden withdrawal/transfer calls absent.
7. 8 USDT legacy test remains, new 29/60/100 eligible funded paper accounts remain separate and contain no double-counted money. Public source testing independent of private credentials.
8. One-box Control Room status/report shows `PUBLIC_OK`, `PRIVATE_READONLY_OK`, `ACCOUNT_RECONCILED`, `EXTERNAL_INTERVENTION`, `DEGRADED`, `LIVE_EXECUTION_BLOCKED` accurately. Never show READY or available capital on incomplete snapshots.
9. Test all prior regression tests and fresh suite on Python 3.11/3.12/3.13; bounded public-only smoke where possible, privacy-safe reports, not a claimed 24h host soak or a live trading test.

## Phase / deployment gates
**A — Build NOW:** KuCoin v4.2 public+private read-only integration adapter with offline mock tests, account discovery, snapshot reconciliation, monitored order/position changes and operator read-only controls. No private credential in code or chat. A live private connection can only be verified after user separately rotates the exposed credential and configures a new General-only API key securely on an approved host.
**B — Then:** Operator dashboard and shadow `previewOrder`/`propose...` interfaces, paper-only market/risk decisions using exchange snapshots. Still no actual trade calls.
**C — Explicit future authorization required:** Limited live *eligible Spot-only* execution adapter if account/regulatory/operations/security acceptance pass. Support cancel/close **DAIINAS-owned** orders with idempotency, risk checks and audit. Any UK retail Futures/Hedge execution remains BLOCKED absent verified legal/product eligibility; do not circumvent via VPN or third-party.
**D — Final acceptance:** durable 24h host, restart/recovery and operational evidence, explicit owner sign-off for each privilege escalation. Never merge into stable without approval. API trading key must never include Withdrawal/Transfer.
